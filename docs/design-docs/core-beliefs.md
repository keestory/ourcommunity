# Core design beliefs

1. 사용자의 현재 상태와 다음 행동이 장식보다 먼저 보인다.
2. 성공 경로뿐 아니라 loading, empty, error, offline, denied 상태를 함께 설계한다.
3. 기존 token과 component를 우선 사용하고 새로운 primitive는 반복 사용 근거가 있을 때만 추가한다.
4. 접근성은 별도 검수 항목이 아니라 정보 구조와 interaction contract의 일부다.
5. 벤치마크에서는 원칙을 배우되 고유한 자산·문구·레이아웃을 복제하지 않는다.
6. 최종 판단은 mockup 의도가 아니라 실제 기기와 렌더링 증거를 기준으로 한다.

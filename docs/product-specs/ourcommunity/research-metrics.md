# 사용자 문제 검증과 측정 계획

상태: 실행 전 계획 / 목표 수치 미승인 · 2026-10-29

핵심 질문은 **그룹이 우리 앱으로 자발적으로 이동해 멤버끼리 대화를 이어가며, 함께 키우는 공간이 소속감과 재참여에 도움이 되는가**이다. 운영 편의·꾸미기 선호·호의적인 반응을 이 질문의 답으로 대체하지 않는다. 인용 근거는 [근거 기록](evidence-decisions.md), 제품 가설은 [brief](product-brief.md)를 따른다.

## 1. 검증 계획 — 인터뷰·연락·파일럿은 아직 실행하지 않음

| 단계 | 대상·방법의 제안 | 수집할 증거 | 반증/중단 조건 |
|---|---|---|---|
| 최근 행동 인터뷰 | 운영자와 비운영자, 적극/조용한/신규/이탈 멤버를 나눠 8–15명 정도를 검토용 계획으로 둠 | 최근 실제 운동 모임의 대화→결정→참여→다음 대화, 기존 그룹 이전 실패, 시간/비용/불편 | 앱 이동 이유보다 기존 관계·설치 부담이 압도하거나 운영자만 가치 인정 |
| 러닝/박스 비교 | 한국·러닝 우선은 임시안, 박스는 반증 비교 후보. 도시·접근 가능한 모집 풀 미정 | 누가 도구를 결정하는지, 회원 자격/예약 원장, 운동 후 대화·시설 소속 | 박스 요구가 예약/회원권 교체 없이는 성립하지 않거나 세그먼트가 서로 다른 문제 |
| 핵심 과업 비교 | 동의 받은 대표 기기에서 초대→인증→설치→첫 대화→알림 복귀를 관찰 | 실패 단계, 도움 요청, 권한 거절, 정확한 방 복귀, 설치 수용성 | 과업을 설명해야만 완료하거나 알림 없이는 대화 복귀 불가 |
| 공동 공간 비교 | [공동 성장 계획](shared-growth.md)의 저충실도 방향·활기 표현을 비교 | 변화 원리 이해, 소속감·압박·프라이버시 예상, 신규/부상/소규모 참여자의 경험 | 예쁜 장식만 선호하거나 활동 감시/강요·열등감을 유발 |
| 자발적 그룹 이전 실험 | 명시적으로 동의한 그룹의 운영자·멤버가 직접 가입; 작고 관찰 가능한 범위부터 | 운영자 독촉 없는 대화, 외부 재전달, 다음 모임까지 복귀, 가입하지 않은 이유 | 외부 메신저 재전달을 계속해야만 참여하거나 대화가 관리자 방송에 그침 |

8–15명이나 Game 프로토타입의 10–20명은 스킬의 권장 범위를 참고한 계획이며 합의된 모집 목표·예산·실적이 아니다. `5크루+3박스+200명/8주`, `크루장10명`은 과거 AI 제안으로 채택하지 않았다. 실제 연락·모집·인센티브·파일럿 기간·데이터 처리에는 별도 범위 확인과 참여자 동의가 필요하다.

## 2. 질문과 조사 윤리

- “새 앱을 쓰실 건가요?” 대신 최근 모임 한 건을 시간순으로 설명받는다. 누가 언제 무엇을 찾고 누구에게 다시 물었는지, 운동 뒤 어디서 다시 대화했는지 묻는다.
- 운영자에게는 공지/명단/외부 재전달/신고 처리의 실제 사례와 부담을 묻고, 멤버에게는 가입하지 않거나 말을 멈춘 이유·다른 사람의 이동이 필요한지를 별도로 묻는다.
- 그룹 이전 의향, 설치/알림 과업, 공동 성장의 의미, 실제 반복 행동을 각각 기록한다. 운영자의 호응을 전체 멤버 동의나 구매 의사로 해석하지 않는다.
- 채팅 원문·연락처·GPS·건강정보를 요청하거나 스크래핑하지 않는다. 당사자가 경험을 설명하는 방식으로 시작하고 원문이 꼭 필요한 연구는 별도 목적·동의·비식별·보관 검토 후 진행한다.
- 녹음·인용·사진·기여자 이름 공개는 각각 선택 동의. 식별 명단과 연구 기록을 분리하고 접근자·삭제일을 먼저 정한다. 침묵·휴식·장애·부상을 평가점수로 만들지 않는다.
- 공정성 표본에는 작은 그룹, 새 멤버, 일정 참여가 어려운 사람, 도구 변경에 부정적인 사람을 포함한다. 장애·부상 상태를 증명하거나 의학정보를 제출할 필요는 없다.

## 3. 지표 정의 — 내부 평가용 제안, 성과 아님

현재 모든 값은 **미측정**이다. 아래 수치 조건·관측창은 비교 가능한 정의를 위한 제안이고 사업 목표/합격선은 사용자와 검증 전에 합의한다. 분모가 0이면 0%가 아니라 `N/A`, 관측창이 끝나지 않으면 `관측 중`으로 표시한다.

내부 시간은 UTC, 운영 표시와 달력 주는 `Asia/Seoul`을 준비 기본값으로 삼는다. 아래 `t0+7d`는 정확한 경과 7일이며 달력 주 집계와 섞지 않는다. 운영 중단·탈퇴·그룹 해산을 좋은 수치만 남기려고 분모에서 사후 제거하지 않는다. 사전 정의된 테스트 계정/봇/내부 직원 계정만 별도 분류한다.

| ID / 지표 | 분자 | 분모·관측창 | 해석·한계 |
|---|---|---|---|
| M01 그룹 단위 이전 도달률 | 사전 합의한 전환 기준을 만족한 그룹 수 | 이전 실험에 동의하고 관측창이 끝난 모든 그룹 수 | 전환 기준은 신규 가입 비율+실제 대화+외부 재전달 부담을 함께 합의. 현재 임계값 미정 |
| M02 동의한 초대 대상의 가입 도달 | 7일 안에 직접 가입한 고유 멤버 수 | 동의 기반으로 확정한 초대 대상 수 | 주소록 수집 금지. 정확한 분모 확보 동의가 없으면 계산하지 않고 초대 링크 전환과 구분 |
| M03 첫 대화 참여율 | 가입 후 7일 안에 서버 저장된 첫 유효 메시지를 보낸 비운영자 수 | 가입 후 7일이 지난 비운영자 계정 수 | 시스템/봇/중복/삭제·스팸 판정 메시지 제외 규칙 고정. 가입 당일 자동 환영은 참여 아님 |
| M04 멤버 주도 대화 그룹 | 기간에 서로 다른 비운영자 간 실제 응답이 이어진 그룹 수 | 관측 기간을 충족한 그룹 수 | 검토용 조건은 최소 2명 간 교류. 자동 판정만으로 ‘독촉 없음’ 추론 불가; 동의한 운영 관찰과 교차 확인. 외부 공개 k와는 별개 |
| M05 다음 모임까지 대화 복귀 | 첫 참여 이후 다음 예정 모임까지 다시 대화에 참여한 고유 멤버 수 | 다음 모임 시점까지 관찰된 해당 첫 참여 코호트 | 다음 모임이 없거나 취소된 경우 별도 집단. 메시지 수 증가만으로 성공 판정 안 함 |
| M06 운영자 2주 반복 사용 | t0+7d 이상 t0+14d 미만에 공식 공지·일정/출석·모더레이션 중 의미 있는 작업을 다시 한 그룹 수 | 첫 의미 있는 운영 작업 t0부터 14일 관찰된 그룹 수 | 여러 운영자는 group 단위로 중복 제거. 읽기/자동작업 제외; 운영 부담이 증가한 것인지 함께 확인 |
| M07 신청→실제 출석 | 실제 출석 present인 고유 account/event 쌍 | completed 회차에서 한 번이라도 confirmed된 고유 account/event 쌍 | 확정 후 취소·노쇼도 분모에 포함. cancelled 회차는 분리 보고, 대기만 한 사람 제외. 이른 취소와 미체크 비중 병기 |
| M08 확정 참가자의 노쇼율 | 회차 종료 후 확인된 absent 수 | 회차 시작 직전 confirmed였던 고유 account/event 쌍 | 미체크를 노쇼로 대체하지 않음; unmarked율·출석 완결률을 함께 보고 |
| M09 4주 운동 재참여 | 첫 present t0 후 [t0+21d, t0+28d)에 다른 completed 회차에서 present인 고유 멤버 | 최초 present 후 28일이 지난 고유 멤버 코호트 | 4주차 rolling retention. 같은 그룹/전체 그룹을 구분. 새 출석 이력으로 과거 분모를 바꾸지 않음 |
| M10 4주 대화 유지 | 첫 유효 비운영자 메시지 t0 후 [t0+21d, t0+28d)에 다시 유효 메시지를 보낸 멤버 | 첫 유효 메시지 후 28일이 지난 비운영자 코호트 | 읽기만 하는 멤버의 가치가 없다는 뜻 아님. 읽기 복귀는 별도 지표이고 개인별 공개하지 않음 |
| M11 외부 재전달 부담 | 운영자가 앱 내용을 외부에 다시 전달한 건수/시간 | 해당 기간의 운영 그룹 수 및 모임 회차 수를 각각 병기 | 동의한 수기 자기보고로 시작. 외부 메시지를 수집하지 않으며 보고 누락 한계 표시 |
| M12 공동 기여 참여의 폭 | 해당 기간 검증된 기여를 한 고유 멤버 수 및 기여 종류 수 | 관측 시작 시점의 활성 가입 멤버 수, 신규 가입 별도 코호트 | 기여량 순위 아님. 출석 불가자의 대체 기여·무기여 선택권과 조작/반려/이의제기를 병기 |
| M13 공동 공간 이해·소속감 | 변화 이유·공동 귀속·알림/활기 비공개 경계를 정확히 설명한 참가자 수; 자기보고 주제 | 해당 과업을 수행한 동의 참가자 수 | 과업 이해와 소속감 자기보고는 별도. 클릭/장식 해금 수로 대체하거나 인과 효과로 단정하지 않음 |

`M04`는 초기 정의안이다. 운영자 독촉 여부는 메시지 내용 AI 분석으로 추론하지 않는다. 직접 관찰 또는 참여자 동의 아래 운영 기록을 보며 불명확하면 `미확인`으로 남긴다. 공개 활기 표현에 이 표의 정확한 수치나 개인 식별자를 사용하지 않는다.

## 4. Guardrail과 중단 조건

| 영역 | 함께 볼 지표·증거 | 대응 제안 |
|---|---|---|
| 프라이버시 | 잘못된 대화/첨부 노출, 소수 집계 재식별 가능성, 삭제 지연 | 심각한 노출은 실험 중단·접근 차단·사건 대응; 원인 권한/집계 설계로 복귀 |
| 대화·공동 기여 | 스팸/봇·자작 승인·신고·뮤트·반려·번복, 조용한 멤버의 압박 경험 | 메시지/운동량 보상 제거, 집계 상한·독립 검토·접근성 재설계 |
| O2O | 정원 초과·중복 신청·자리 회수 실패, 미체크·노쇼·일정 변경 미인지 | 해당 흐름 중단·원장/알림/운영 계약 수정 후 재검증 |
| 운영 가능성 | 그룹당 신고/검수 시간, 외부 재전달 시간, 애셋 제작/승인 부담 | 약속된 대응을 제공할 수 없으면 규모 확대 중단 |
| 이동과 정착 | 운영자만 대화, 멤버 이탈, 다음 모임까지 복귀 없음 | Gate 0/2로 복귀, 장식/기능 추가로 전환 이유 부재를 덮지 않음 |

목표 수치와 연속 실패 횟수는 검증 전에 합의해 decision log에 기록한다. 제품 증거 없이 통계 유의성·성장률·리텐션 개선을 주장하지 않는다. 작은 표본은 원시 건수·관측 완료율·편향·사례를 함께 보고한다.

## 5. 최소 이벤트와 개인정보 계약 초안

| 이벤트 계열 | 필요한 최소 의미 | 제외할 데이터 |
|---|---|---|
| invite_opened / membership_activated | 초대 흐름/그룹·익명 세션 또는 동의한 가명 계정·가입 시각 | 초대 원문 토큰, 주소록·메신저 ID |
| message_persisted / conversation_read | 중복 제거용 ID·group/conversation·가명 actor·수신/읽음 cursor | 메시지 본문·인용·감정·정확한 접속 상태의 공개 |
| notification_attempt / notification_opened | 전송 시도/실패·복귀 대상·선호 버전 | device token·잠금화면 내용. 전송 ACK를 실제 읽음으로 오인 금지 |
| registration_changed / attendance_revised | 회차·상태·revision·서버 시각·중복 키 | 건강정보·정확한 위치·무제한 수정 이유 원문 |
| contribution_verified/reversed / space_revision | 원천 ID·규칙 버전·상태·집계 그룹·장식 변화 | 개인 순위, 사진/메시지 원문, 허위 성과 |
| report_status_changed / deletion_processed | 안전 사건의 최소 상태·처리 지연 | 신고 본문·민감 증거·대상 식별자를 일반 분석 저장소로 복제 금지 |

재시도는 event ID로 중복 제거하고 서버 상태 변경과 outbox를 결합한다. 보관 기간·접근 담당·삭제/철회 시 분석 재계산·모델 학습 사용 금지는 Gate 5 전 확정한다. 동의 없이 채팅 내용 AI 분석을 하지 않는다. 현재 수집기·분석 SDK·이벤트 파이프라인은 구현/설치하지 않았다.

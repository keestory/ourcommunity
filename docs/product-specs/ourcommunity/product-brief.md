# Product brief — 함께 대화하고 커뮤니티를 키우는 운동 참여자

문서 상태: 제안 / 미승인 · 작성일: 2026-10-29 · 담당 역할: Product Orchestrator

## 확정된 목적과 현재 상태

사용자가 확정한 것은 스포츠를 **직접 즐기는 사람**을 위한 서비스, 러닝 크루·크로스핏이라는 후보, **우리 앱에서 커뮤니케이션을 유지한다**는 목표, **멤버의 행동이 커뮤니티·다니는 시설을 함께 꾸미고 키우는 애셋으로 이어지는 비전**이다. 구체적인 기여 규칙·애셋·지역·플랫폼·요금은 미정이다. 한국·러닝 우선은 준비용 가정이며 확정된 사용자 선택이 아니다. 원문 발언과 출처 한계는 [근거 기록](evidence-decisions.md)에 있다.

저장소의 `AGENTS.md`, `.codex/`, Python 실행기는 개발자를 돕는 하네스다. 이용자용 채팅·인증·예약·출석·모바일 앱은 구현되지 않았다. 하네스 테스트의 통과를 서비스 동작이나 수요 증거로 쓰지 않는다.

## 문제와 가치 제안 — 검증할 가설

| 대상 후보 | 끝내려는 일(JTBD) | 확인할 현재 행동 | 제안 가치 |
|---|---|---|---|
| 일반 멤버 | 함께 운동할 사람과 대화를 이어가고 다음 만남에 참여 | 최근 실제 그룹 대화, 일정 탐색, 참석 결정, 운동 후 재대화 | 대화 맥락 안에서 공지·일정·신청·활동이 연결됨 |
| 크루 운영자 | 멤버가 다시 찾아오는 대화를 만들고 만남을 운영 | 공지 재설명, 반응 없는 대화, 명단·노쇼 처리 시간 | 대화와 공식 정보를 구분하고 운영 상태를 함께 확인 |
| 크로스핏 박스 운영자/코치 | 운동 전후 관계와 재참여를 유지 | 기존 회원 앱, 수업 정원, 체험자 접근, 기록 공유 방식 | 커뮤니티 기능의 독립적 가치가 있는지 확인; 예약·WOD 시스템 교체는 미정 |

위 문제는 관찰된 고객 불만이 아니다. ‘메신저와 다른 앱 하나를 더 설치할 만큼 가치가 있는가’, ‘기존 대화 상대가 함께 이동하는가’가 가장 큰 반증 질문이다. **일정 관리만 좋아졌지만 대화가 기존 메신저에 남으면 사용자 목표를 충족하지 못한다.**

핵심 가치 가설은 `대화/운동/도움 → 검증된 공동 기여 → 함께 변하는 공간과 애셋 → 소속감 → 다시 대화하고 참여`다. [공동 성장 문서](shared-growth.md)의 디지털 공간은 검증할 표현안이며 실제 시설 공사·물품 제공·금전 보상을 뜻하지 않는다. 메시지 수·운동량·개인 랭킹으로 모든 행동을 평가하는 안은 채택하지 않았다.

최신 사용자 요구는 **채팅 원문을 공개하지 않으면서 대화의 활발함을 독특하게 표현**하는 것이다. [공간·활기 레퍼런스](activity-patterns.md)는 이 요구를 공동 공간과 연결한다. 핵심 설명의 제안은 “대화를 공개하는 게 아니라, 함께한 시간이 만든 공간을 보여주는 스포츠 커뮤니티”다. 문구·2D 클럽하우스·불빛 등의 미학은 사용자 확정이 아니다.

## 산업과 역할

- 주 산업 `Community`: 반복 대화, 소속, 공지와 이용자 콘텐츠가 핵심이다.
- 보조 산업 `O2O`: 온라인 일정·신청이 실제 운동·출석·노쇼와 연결된다.
- 보조 산업 `Game`: 공동 성장·꾸미기·피드백 규칙에 Concept/Prototype·중복 보상·조작 방지 기준을 적용한다. 유료재화·거래·확률형 상품은 범위 밖이다.
- `AI Product`를 선택하지 않는다. 개발용 에이전트 하네스의 존재는 소비자 제품에 AI 기능이 필요하다는 근거가 아니다.
- 문서 작성은 L1. 향후 채팅·인증·개인정보·권한 구현은 L4 검증이 필요하다.
- `discoverability: required` — 초대 링크·공개 소개·로그인 복귀의 설계 영향. 기본 비공개 그룹은 검색 색인을 제안하지 않는다.
- `store_compliance: not-applicable` — 이번은 제출/구현 없는 문서 작업. 네이티브를 선택하면 Gate 4–5에서 `required`로 재판정한다.
- `competitive_benchmark: required` — 현재 핵심 전환 가설에 경쟁·대체재 근거가 필요하나 아직 미검증이다.

## 공통 요구와 달라질 요구

| 영역 | 공통 초안 | 러닝 크루에서 확인할 점 | 박스에서 확인할 점 |
|---|---|---|---|
| 대화 | 그룹 대화·공지·신고·뮤트·알림 | 비정기 모임과 초보자 유입, 페이스별 대화 분리 필요성 | 코치/회원/체험자의 대화 권한, 기존 앱과 중복 부담 |
| 가입 | 초대 후 인증·규칙 동의·가입 승인 선택 | 열린 모집과 지인 초대의 균형 | 회원 확인 방식; 회원권/결제 연동 필요성은 별도 가설 |
| 일정 | 회차별 시간·정원·신청·대기·취소 | 집결지 변경, 날씨 취소, 페이스/거리 안내 | 반복 수업·코치·장비 정원·휴무·회차 간 buffer |
| 현장 | 운영자 출석·수정 이력·참가자 문의 | 집결지 혼선, 지각, 현장 추가 참여 | 체험 동의·현장 안내·수업 중단·대체 수업 책임 |
| 활동 이력 | 본인 참가·출석 이력은 비공개 기본 | 순위·성능 경쟁 없이 재참여에 도움 되는가 | WOD·부상·신체 기록이 정말 필수인지; 현재 제외 제안 |

박스 요구가 회원권·요금·회계·전문 운동 기록 교체로 확대되면 같은 MVP로 합치지 않고 Gate 0–3에서 범위를 다시 검토한다.

## 단계별 범위 — 모두 제안, 날짜 약속 아님

| 단계 | 제안 산출물 | 진입 조건 / 검증 | 이번 상태 |
|---|---|---|---|
| 준비 | 문제 인터뷰·전환 장벽·기기·대체재 연구 계획과 초안 | 사용자 결정과 외부 조사 권한 확보 | 문서만 작성 |
| 핵심 커뮤니티 MVP | 초대·가입, 그룹 텍스트 채팅, 공지, 안읽음·뮤트·알림, 일정 카드·참가·출석, 신고·차단·운영 도구, 최소한의 공동 공간·검증된 기여 표현 | Gate 0–5와 공동 성장 Concept/Prototype 검증; 실제 대화/소속감/재참여 확인 | 미승인 / 미구현 |
| 커뮤니티 확장 | 발견 가능한 그룹 소개, 프로필 공개 선택, 필요성이 입증된 이미지 공유·주제별 방 | 핵심 그룹이 반복 대화하고 안전 운영 가능; 사용자별 공개 동의 | 미승인 |
| O2O·사업 확장 | 박스 체험/드롭인, 시설·대회 연결, 필요한 과금 실험 | 공급/책임/가격/환불·수수료 검증, 별도 보안·사업 Gate | 미승인 |

이미지 공유가 첫 대화에 필수라는 근거가 나오면 Gate 4에서 MVP에 올릴 수 있다. 그때 개인정보·저작권·검수·보관 비용과 [첨부 계약](data-architecture.md)을 함께 승인해야 한다. 채팅 자체는 후속 단계로 미루지 않는다.

## 초기 범위에서 제외할 제안과 이유

| 항목 | 제외 제안 이유 / 다시 포함할 조건 |
|---|---|
| 전체 DM·음성/영상 통화 | 그룹 지속 대화와 다른 안전·신뢰·운영 문제. 별도 수요·미성년자·괴롭힘 검토 후 판단 |
| 공개 대규모 피드·팔로워 경쟁·추천 알고리즘 | 초기 그룹 내 반복 행동의 검증을 흐릴 수 있음. 공급·운영·노출 품질 근거 후 검토 |
| GPS 추적·상시 위치·성능 랭킹 | 전환 가치가 확인되지 않았고 민감 위치·배터리·스포츠 편차가 큼 |
| PG·쇼핑·정기 멤버십 관리 | 과금·환불·회원권 정책이 미정. 대화 유지 검증과 구별 |
| WOD 전문 기록·건강/부상 관리 | 러닝과 공통 요구가 아니며 민감 데이터와 박스 시스템 범위가 커짐 |
| 카카오 대화/연락처 자동 가져오기 | 사용자가 승인하지 않았으며 이전 상대의 동의·권한·보관 문제가 있음 |

## 사용자가 결정할 중요한 질문 — 최대 3개

| ID | 질문 | 추천 기본값 | 결정이 바꾸는 것 |
|---|---|---|---|
| Q1 | 첫 검증 종목·지역과 접근 가능한 그룹은? | 한국의 러닝 크루 우선, 박스는 비교 후보; 도시/실제 그룹 미정 | 모집 대상·현장 책임·조사 현실성 |
| Q2 | 주 기기와 앱 설치 수용성, 기대하는 알림 복귀 경험은? | 네이티브/크로스플랫폼과 PWA를 같은 핵심 과업으로 비교 후 결정 | 플랫폼·인증 복귀·푸시·운영/스토어 비용 |
| Q3 | 함께 키울 공간은 어떤 모습이며 어떤 기여가 의미 있는가? | 디지털 클럽 공간과 출석·도움 같은 다른 기여를 표현하는 소수 애셋을 비교 | 공간 은유·접근성·해금/합의 규칙; 실물 지원과 분리 |

답변 전 추천값은 확정 정책이 아니다. 세부 수익모델, 성공/실패 임계값, 운영 예산·책임자는 초기 증거를 얻은 뒤 묶어서 결정한다.

## 성공·중단 기준

성공 후보는 가입 숫자보다 **멤버끼리 반복 대화하는 그룹**, **함께 기여했다는 이해와 소속감**, **운영자의 반복 운영**, **신청의 실제 출석**, **4주 대화 유지와 운동 재참여**다. 꾸미기 클릭 수를 소속감으로 대체하지 않는다. 분모·관측창은 [측정 계획](research-metrics.md)에 있다. 수치 목표는 미승인이다.

자발적 대화가 없이 운영자 공지만 소비하거나, 기존 메신저 없이는 다음 참여가 성립하지 않거나, 안전 운영비가 감당되지 않으면 기능을 추가하기 전에 Gate 0/2로 돌아간다. 인터뷰의 호의적 반응만으로 구현을 승인하지 않는다.

# 공동 성장 경험 — 함께 만든 공간

상태: 사용자 비전을 위한 제안 / 미승인 규칙 · 2026-10-29 · 구현·이미지 생성·외부 사용자 시험 없음

## 확정 비전과 제안 경계

사용자는 사람들의 행동이 참여한 커뮤니티/다니는 시설을 꾸미는 애셋이 되고 함께 키우는 경험을 원한다(E11). 앱 내부의 지속 커뮤니케이션(E04)은 유지한다. 채팅 화면 옆에 무관한 게임을 붙이는 것보다 그룹의 관계·활동·도움을 공동 공간에서 되돌아볼 수 있는 순환을 검증한다.

사용자의 추가 요구(E12)는 채팅 원문 비공개와 독특한 활기 표현이다. 최근 분위기와 영구 공동 자산은 분리한다. 최근 대화가 줄어도 기념물·추억을 잃지 않으며 조용한 공간도 완성된 고유 표현을 갖는다. 실제 레퍼런스와 집계 공개 계약은 [공간·활기 패턴](activity-patterns.md)에 있다.

저위험 기본 제안은 **디지털 공동 공간과 비금전 장식 애셋**이다. 실제 체육시설 공사·기부·장비 지급·경제적 소유권은 약속하지 않는다. 유료 재화, NFT/토큰, 거래, 환금, 확률형 상품, 개인 랭킹은 이번 제안에 포함하지 않는다. ‘모든 행동’이라는 비전이 모든 메시지·운동량을 무조건 수집·점수화하라는 요구는 아니다.

주 산업은 Community, 보조는 O2O와 Game이다. Game의 Concept/Prototype, 서버 권위·중복 지급·동기화·조작 방지 기준을 적용한다. 유료 경제/결제 Gate는 현재 비적용이며 나중에 도입하려면 별도 승인·정책·사업 검증이 필요하다.

## 30초 이해 루프 — 검증할 표현

`그룹에서 대화·도움·운동 참여 → 확인 가능한 기여 후보 → 승인/취소 가능한 공동 기여 → 공간의 변화·장식 선택 → 함께한 이유를 이해 → 다음 대화/활동`

첫 체험에서는 ‘누군가가 무엇을 했고 왜 우리 공간이 변했는가’를 설명 없이 이해할 수 있는지 본다. 장식의 신기함, 소속감, 보상 압박, 다음 참여 의지는 서로 다른 질문으로 측정한다. 누가 가장 많이 했는지 경쟁시키거나 연속 출석이 끊겼다고 그룹을 쇠퇴시키는 안은 기본에서 제외한다.

## 행동→기여→공간 표현의 후보 비교

아래는 선택지이며 동시에 구현하거나 확정한 규칙이 아니다. 개인 이름 공개는 선택 동의와 권한을 전제로 한다.

| 기여 후보 | 확인할 수 있는 신호 | 공동 표현 예시 | 장점 가설 / 위험 |
|---|---|---|---|
| 실제 운동 참여 | 운영자 확인 출석 + 수정/이의제기 | 모임 기억을 담은 공동 벽면의 한 조각 | 오프라인 참여가 연결되지만 운영자 허위 확인·부상자 배제 위험 |
| 공동 활동 완수 | 회차와 서로 독립된 참여자의 확인 | 공동 정원·클럽 공간의 테마 애셋 | ‘함께’가 드러나지만 큰 그룹이 항상 유리할 수 있음 |
| 도움이 되는 교류 | 도움받은 멤버의 자발적 확인, 필요 시 독립 검토 | 환영 공간·도움의 기록·공동 배지 | 신입 환영/안내가 인정되지만 품앗이·인기투표·운영자 자작 승인 위험 |
| 사진·후기 | 작성자 동의, 등장인물·공개 범위, 검수/철회 | 비공개 공동 앨범/기억 애셋 | 운동 후 대화에 연결되지만 초상·위치·권리·보관 위험; MVP 포함 미정 |
| 쉬는 동안 기여 | 일정 안내·초보자 응원·안전한 경험 공유 등 | 운동량과 무관한 다양한 애셋 표현 | 신규·부상·장애·시간제약 참여자 포함. ‘도움’의 강요/감시를 피해야 함 |

메시지 수·접속 시간·칼로리·거리·속도에 비례한 보상은 기본 후보에서 제외한다. 더 많이 뛰거나 무리해야 기여할 수 있는 설계, 읽기만 하는 멤버의 처벌, 출석하지 못한 사람의 이름 공개는 제안하지 않는다.

## 공간 방향 후보 — 아직 시각 취향은 미확정

| 방향 | 구조·상호작용 | 비교할 이유 |
|---|---|---|
| A. 공동 클럽 공간 | 작은 평면 공간에서 공동 장식을 선택/배치, 각 애셋에 관련 활동 설명 | 소속 공간을 직접 키우는 감각; 배치 권한·접근성·운영 갈등 확인 |
| B. 커뮤니티 기억 정원 | 검증된 다양한 기여가 그룹의 기억 영역을 채우고 이야기를 연다 | 그룹 규모·운동 실력 대신 다양한 참여를 표현할 가능성 |
| C. 시설의 디지털 게시/꾸미기 공간 | 실제 시설의 허락된 정체성을 쓰되 실제 개선과 명확히 구분 | 박스 소속감을 연결할 가능성; 시설 상표·사진 동의와 변경/탈퇴 처리 필요 |

2~3개 저충실도 방향을 같은 기여·그룹 규모·빈 상태로 비교한다. 실제 시설 사진/브랜드를 무단 사용하지 않는다. 아직 스타일·색상·캐릭터·애셋 라이선스·브랜드 선호를 승인받거나 학습한 결과는 없다. Community는 관계·안전, Game은 피드백·상태 명확성, O2O는 실제 활동의 확인을 우선한다.

## 검증·공정성·합의 계약 초안

- 모든 기여 후보에 source event ID, 규칙 버전, 검증 상태를 둔다. `(group, source_event, rule_version)` 중복 반영 금지. 클라이언트가 기여량·애셋을 직접 확정하지 않는다.
- 승인/정정/무효/이의제기를 분리한다. 출석 수정·메시지 삭제·사진 동의 철회로 원천이 바뀌면 보상 원장을 보정하고 이유를 당사자에게 알린다. 중복 이벤트/재시도/백업 재생이 애셋을 늘리지 않아야 한다.
- 메시지 도배·봇·다계정·자작 도움 확인·운영자 자기 승인에는 속도/빈도 제한, 독립 검토, 감사, 이의제기 경로를 둔다. 임계값·기간·검토 인력은 아직 미정이다. AI만으로 제재하지 않는다.
- 그룹 규모가 달라도 가질 수 있는 경험의 폭을 제한하지 않는 안을 비교한다. 절대 횟수 목표 대신 일정 기간의 공동 목표·기여 종류 다양성 등을 시험하되 작은 그룹 식별·평가 부담도 확인한다.
- 개인 체력·시간·연령·장애·부상 공개를 요구하지 않는다. 운동량과 무관한 기여·읽기 참여·쉬는 선택을 존중한다. 비참여자를 표시하거나 불이익을 주지 않는다.
- 꾸미기 권한은 운영자 독점, 위임 편집자, 구성원 제안/승인의 대안을 비교한다. 추천은 구성원 제안 + 위임 편집 + 버전 이력/되돌리기이며 합의 기준·운영자 거부 사유는 미정이다.
- 그룹 애셋은 공동 디지털 이용권/표현으로 제안한다. 특정 사용자의 재산·현금 가치라고 표시하지 않는다. 애셋 출처·라이선스·편집권·시설 상표 사용 권한은 별도 관리한다.
- 멤버 탈퇴/강퇴 때 공동 공간은 즉시 훼손하지 않는 안을 검토한다. 공개 기여자 표시 제거/익명화, 기여 무효화와 재산 환수의 구분, 시설 변경/그룹 해산/소유자 이전의 애셋 귀속은 **열린 결정**이다.
- 잘못 얻은 기여를 정정할 때 다른 멤버의 장식을 몰래 지우지 않는다. 보정 원장과 공간 버전을 분리하고 운영자 복구/이의제기 절차를 확인한다. 정확한 되돌리기 정책은 승인 전이다.
- 사진 철회 시 사진 본문·썸네일·장식 변형·공유 캐시를 추적 삭제한다. 사진을 제거한 추상 애셋 유지 가능성은 동의/저작권 정책에 따라 정한다. ‘비공개 사진을 올렸으니 모든 멤버 공개 허용’으로 해석하지 않는다.

## 필요한 추가 개념 모델

| 객체 | 목적 / 불변조건 |
|---|---|
| ContributionCandidate | group, source_event, eligible_rule_version, pending/verified/rejected/reversed; 근거 최소화 |
| ContributionReview | 독립 확인자, 이유, 시점, 이의제기; 자기 승인·대리 권한 검사 |
| GroupGrowthLedger | 중복 불가 원천 키와 보정 이벤트; 집계치만 덮어쓰지 않음 |
| AssetDefinition / GroupAsset | 라이선스·조건 버전·공동 사용 범위·해금 출처; 양도/거래/가격 없음 |
| SharedSpace / LayoutRevision | 그룹/시설 참조, 편집 권한, 낙관적 버전, 되돌리기·승인 이력 |
| ConsentReference | 선택적 사진·기여자 표시의 공개 범위/철회; 민감 본문은 원장에 복제하지 않음 |
| ActivitySnapshot | 승인된 넓은 기간·지연·인원 기준의 coarse 단계와 정책 버전; 개인/원문/정확한 건수 비포함 |

필요하면 읽기용 공간 상태를 계산하지만 메시지/출석 원장을 대체하지 않는다. 보정·새 규칙 적용·그룹 합치기/분리 때의 이관 정책은 미정이며 자동 소급 보상을 하지 않는다.

## 가벼운 프로토타입 계획 — 실행하지 않음

1. 종이/정적 저충실도 자료로 A/B/C를 비교한다. 실제 데이터·시설 사진 대신 명시된 가상 예시를 쓰고 기능이 작동한다고 표현하지 않는다.
2. 첫 대화→일정 참여→기여 확인→공동 공간 변화→장식 제안 과업을 구성한다. 동시에 ‘신규 멤버’, ‘부상으로 출석 불가’, ‘작은 그룹’, ‘출석 정정’, ‘운영자 오남용’ 상황을 제시한다.
3. 먼저 소수의 대표 사용자로 모호한 과업을 수정하고, Game Prototype Gate의 10–20명 목표를 검토용 계획으로 둔다. 숫자는 확정 모집·진행 성과가 아니다. 인터뷰/모집은 별도 승인·동의 이후다.
4. 설명 없이 변화 이유를 이해하는지, 함께했다는 느낌과 다시 대화할 이유가 있는지, 조작 방법을 떠올리는지, 압박·배제·동의 혼란이 있는지를 기록한다. 화려함/보상 기대만 높으면 재설계한다.
5. 정성 검증 이후에만 별도 구현 권한과 Gate 5를 검토한다. 프레임레이트·메모리·배터리·저성능 기기·motion 감소·스크린리더 대체 표현은 실제 프로토타입에서 시험할 미래 항목이다.

Game Concept Gate의 비교 사례 10개 이상 분석, Prototype Gate의 사용자 시험, 성장 속도/콘텐츠 공급/조작 방지 검증은 아직 하지 않았다. 따라서 Game Gate는 **Blocked / 미검증**이다. 유료 경제는 범위 밖이지만 비금전 애셋에도 해금 원천·보유/배치 상한·보정·회수·그룹 수명주기 표를 확정해야 한다. 점수·가중치·임계치·시즌·제작 주기를 임의로 채우지 않는다.

## 수용 기준 — 미래 검증 대상

| ID | 완료 기준 |
|---|---|
| AC-G01 | 공동 기여의 원천·검증 상태·공간 변화 이유를 멤버가 이해하고 출석/동의 정정이 공간/공개 이력에 반영됨 |
| AC-G02 | 재시도/봇/자작 승인/원장 재생으로 중복 기여·해금 불가. 독립 검토·보정·이의제기와 규칙 버전이 존재 |
| AC-G03 | 개인 운동량·메시지 수 경쟁, 침묵/휴식 벌점·연대 실패·영구 자산 감쇠 없음. 신규/작은 그룹/출석 어려운 사람의 참여 경로 존재 |
| AC-G04 | 편집·합의·소유권 이전/시설 변경·탈퇴·해산 정책에 따른 권한·감사·복구, 사진·이름 동의 철회 경로 존재 |
| AC-G05 | 비회원은 승인된 coarse 집계만 접근. 작은 그룹 억제·지연·고정 창·공개 선택/고지·삭제 영향 검증; 본문·개인활동·감정추론·정확한 접속 수 노출 없음 |
| AC-G06 | 최근 활기와 영구 자산을 구분하고 지표가 낮거나 비공개여도 열등함을 암시하지 않음. 동작 감소·텍스트·스크린리더 대체 표현 제공 |

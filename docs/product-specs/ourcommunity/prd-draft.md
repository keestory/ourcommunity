# PRD 초안 — 그룹 대화에서 다음 운동까지

상태: 미승인 / 미구현 · 2026-10-29 · 근거: [brief](product-brief.md), [결정 기록](evidence-decisions.md)

**목표는 앱 안에서 멤버끼리 지속 대화하는 것이다.** 공지·일정·참가·출석은 대화를 운동과 연결한다. 단순 예약 도구의 사용 증가를 커뮤니티 전환 성공으로 대체하지 않는다. 이 문서는 검증할 상호작용 계약이며 확정 UX나 렌더링 검증 결과가 아니다.

## 1. MVP 제안과 전환 이유

제안 범위는 초대 기반 그룹, 텍스트 채팅, 공식 공지, 그룹별 안읽음·뮤트·알림, 대화에 연결된 일정·참가·출석·본인 활동 이력, 신고·차단·운영자 처리다. 그룹당 기본 대화방 1개를 가정하되 실제 대화 주제 분리 필요성은 조사한다.

최신 확정 비전은 멤버의 행동이 함께 커뮤니티/시설을 꾸미고 키우는 경험이며, 채팅 원문은 공개하지 않으면서 대화의 활기를 독특하게 표현한다. MVP의 추가 제안은 [최소 공동 공간·기여](shared-growth.md)와 [최근 활기의 보호된 표현](activity-patterns.md)이다. 영구 기념물과 최근 분위기는 분리하고, 공개 활기는 정책·고지·집계 보호를 충족한 경우의 선택 기능으로 검토한다. 정확한 개인 활동·온라인 수·채팅 내용·감정은 외부에 노출하지 않는다.

전환 가치 가설은 ‘운동 전후의 대화 맥락과 다음 만남의 확정 정보를 같은 공간에서 유지한다’이다. **Heylo에도 채팅과 이벤트 기능이 있으므로 기능 조합 자체는 차별화가 아니다.** 특정 지역·종목의 관계·운영 방식에 더 맞는지, 기존 대안보다 어떤 과업이 나아지는지 검증해야 한다.

전환은 명시적으로 동의한 운영자와 멤버의 자발적 가입이다. 기존 대화·연락처·참가 명단을 자동으로 가져오거나 외부에서 자동 가입/초대하지 않는다. 운영자가 승인한 소개·규칙·다음 일정·첫 대화 주제를 직접 준비하는 방안을 검증한다. 초기 콘텐츠가 없을 때 가짜 멤버·메시지·활동 수를 표시하지 않는다.

## 2. 핵심 흐름과 수용 기준

아래 ID는 [QA 계획](execution-qa.md)의 시나리오와 연결된다. 모든 수용 기준은 미래 구현의 목표이며 현재 통과한 제품 테스트가 아니다.

| ID | 흐름 | 제안 동작 / 완료 기준 |
|---|---|---|
| AC-J01 | 운영자 준비→초대 링크 공유 | 그룹 소개·규칙·운영자·다음 일정·첫 주제가 준비됨. 링크를 생성하고 사람이 직접 공유. 만료/사용 제한/폐기 가능; 연락처 접근 없음 |
| AC-J02 | 초대 열기→인증→원래 그룹 복귀 | 미가입자에게 허용된 소개만 노출. 서명·만료된 복귀 상태로 정확한 그룹/일정에 돌아옴. 외부 URL 리다이렉트와 초대 토큰의 분석 로그 전송 금지 |
| AC-J03 | 규칙 확인→가입/승인→첫 대화 | 인증과 그룹 가입은 별도. 규칙·공개 범위·과거 대화 정책을 안내. 승인 대기자는 대화/명단에 접근 불가. 첫 대화와 공지를 찾을 수 있음 |
| AC-C01 | 메시지 작성→전송 | 서버 저장 후에만 ‘전송됨’. 동일 client message ID 재시도는 1건. 실패/대기 상태와 재시도·취소가 구분됨 |
| AC-C02 | 실시간 수신→재접속 | 서버가 부여한 방별 순서로 표시. 누락 구간 재조회·중복 제거. 뒤늦은 도착이 최신 대화·안읽음 상태를 손상하지 않음 |
| AC-C03 | 읽음/안읽음→다른 기기 | 본인의 방별 읽은 위치는 증가 방향으로만 동기화. 알림 수신을 읽음으로 취급하지 않음. 개인별 읽은 사람 명단은 MVP 제외 제안 |
| AC-C04 | 알림 허용/거절·뮤트→복귀 | 첫 가치 이후 맥락 있는 권한 안내. 거절·OS 차단·뮤트 상태에서도 앱 안 수신함으로 확인. 허용 시 정확한 방/메시지로 복귀하고 권한 재검사 |
| AC-C05 | 공지 고정·수정→공식 정보 확인 | 공지와 일반 대화를 구분. 수정 버전·작성자·갱신 시점 표시. 공지 읽음은 일반 메시지 읽음과 구분; 강제 푸시 우회 없음 |
| AC-E01 | 일정 생성→대화 카드/링크 공유 | 시간·모임 장소 공개 범위·정원·마감·취소 정책이 명확. 카드는 현재 일정 상태를 조회하고 원본 version과 연결 |
| AC-E02 | 가입/신청→확정 또는 대기 | 하나의 일정에 동일 계정의 유효 신청은 1개. 마지막 자리 동시 신청에서 초과 확정 없음. 정원 값은 서버가 판정 |
| AC-E03 | 취소→자리 제안→대기자 수락 | 취소/만료/수락 재시도에 중복 자리 회수·승격 없음. 제안 기한과 신청 마감 중 빠른 시점까지 수락. 응답 없으면 다음 대기자 |
| AC-E04 | 일정 변경/취소→참가자 확인 | 시간·장소 변경 이력과 미확인 표시. 신청/대기를 유지할지 재동의가 필요한지 정책 명시. 취소 일정은 새로운 신청·승격 금지 |
| AC-E05 | 현장 출석→수정/노쇼→본인 이력 | 운영자만 출석 변경. 변경 이유·이전값·수정자를 감사 기록. 미체크를 자동으로 노쇼 확정하지 않고 이의 제기 경로 제공 |
| AC-S01 | 신고·차단→관리자 처리 | 메시지·그룹·계정에서 신고와 도움말 접근 가능. 신고 대상이 신고를 숨기거나 자기 사건을 단독 종결할 수 없음. 처분·이의제기 기록 분리 |
| AC-S02 | 탈퇴·강퇴·정지→접근 종료 | API·소켓·미디어·알림·검색/딥링크에서 서버 권한 제거. 캐시 재열람 제한과 재가입 시 과거 권한 미복구 확인 |
| AC-P01 | 탈퇴·삭제 요청→보관/삭제 | 계정 탈퇴와 그룹 탈퇴를 구분. 메시지/이미지/신고 증거/백업의 보관·익명화·삭제 조건을 고지하고 검증 가능하게 설계 |

주요 경로는 `초대 → 인증·가입 → 첫 대화 → 공지/일정 카드 → 참가 신청 → 운동 → 운동 후 대화 → 다음 모임`이다. 일정만 먼저 열어도 인증 후 해당 일정으로 돌아가며, 승인 후 그룹 대화로 자연스럽게 연결한다.

공동 성장 경로는 여기서 `운동/도움 → 검증된 기여 → 공동 애셋/기념물 → 다음 대화·참여`로 이어진다. 비회원 공간 뷰는 내부 채팅 뷰와 별개이며 공개 설정과 안전한 집계가 없으면 최근 활기를 숨긴다. 해당 수용 기준 `AC-G01–06`은 [공동 성장 문서](shared-growth.md)에 있다.

## 3. 역할·공개 범위 — 제안 정책

| 역할 | 볼 수 있는 것 | 할 수 있는 것 | 금지/제약 |
|---|---|---|---|
| 비로그인 방문자 | 운영자가 공개 승인한 그룹 소개·초대 유효 여부 | 로그인 진입·공개 문제 신고 경로 | 대화·멤버 목록·정확한 집결지·출석·사진 조회 불가 |
| 가입 대기자 | 자신의 승인 상태와 규칙 | 신청 취소·도움 요청 | 가입 성공처럼 표시하지 않음; 대화·활동 접근 불가 |
| 활성 멤버 | 권한 범위 대화·공지·일정, 자신의 신청·이력 | 대화·신청·취소·신고·뮤트·차단 | 남의 연락처·비공개 이력·전체 출석명단 조회 불가 |
| 운영자/코치 | 맡은 그룹의 운영 정보·필요한 참가명단 | 일정·공지·가입 승인·출석·모더레이션 요청 | 타 그룹 접근 금지; 계정 비밀·개인 전체 이력 접근 금지 |
| 소유자 | 자기 그룹의 역할·운영 설정 | 운영자 임명/회수, 소유권 이전 | 마지막 소유자의 탈퇴 전 이전/폐쇄 절차. 본인 신고를 삭제 불가 |
| 안전 담당자 | 배정된 신고·조사에 필요한 최소 증거 | 숨김·일시 제한·제재·이의제기 처리 | 일반 대화 상시 열람 금지. 사건·목적·접근 감사 필요 |
| 탈퇴/강퇴/정지 계정 | 본인 계정 도움말·이의제기·삭제 상태 | 정해진 이의제기·데이터 요청 | 옛 토큰/웹소켓/미디어 URL로 그룹 콘텐츠 접근 불가 |

그룹은 비공개·초대 기본을 제안한다. 가입 전에도 초대 토큰을 가진 사람에게 어느 소개까지 보여줄지는 별도 설정 계약이 필요하다. 링크 보유를 그룹 접근권으로 취급하지 않는다. 정확한 위치는 승인된 참가자 등 업무상 필요한 범위로 더 좁힌다.

새 멤버의 과거 대화 공개는 **열린 결정**이다. 임시안은 가입 이후 대화만, 현행 공지와 미래 일정은 읽기 허용이다. 재가입 시 새 membership epoch를 만들며 과거 방의 읽기 권한을 자동 복구하지 않는다. 운영자가 이 정책을 바꿀 때 기존 작성자의 기대와 동의, 변경 고지·감사를 다시 검토한다.

## 4. 메시지·정원·출석 상태

| 대상 | 상태와 의미 | 주요 불변조건 |
|---|---|---|
| 그룹 가입 | pending → active → left/removed/suspended | active 권한은 요청마다 검사; 복귀는 새로운 가입 절차 |
| 메시지 전송 | local_draft → sending → persisted 또는 failed | persisted는 서버 ACK 이후. 오프라인 큐는 미전송임을 명시; 재접속 후 탈퇴 상태면 폐기 안내 |
| 저장 메시지 | visible → edited/deleted/hidden | 삭제/숨김은 인용·검색·알림 프리뷰·캐시에 반영; 순서 복구용 tombstone과 본문 보관은 분리 |
| 일정 | draft → published → completed 또는 cancelled | 취소 후 신청/승격 없음. 메시지 카드가 DB의 실제 상태를 대체하지 않음 |
| 신청 | confirmed / waitlisted / offered / cancelled / expired | confirmed + offered의 예약 좌석 ≤ capacity. 대기자는 수용 여부를 확인하기 전 참석 확정 아님 |
| 출석 | unmarked / present / absent / excused | confirmed와 출석은 별개. 노쇼는 종료 후 확인된 absent로만 분류; 미측정은 따로 보고 |

대기순서는 서버가 확정한 최초 유효 신청 순서를 제안한다. 자리 제안 유효시간은 제품 결정 필요(검토용 예: 30분). 막판 신청 마감 이후 승격하지 않는다. 신뢰할 수 없는 클라이언트 시각이나 푸시 도착 여부로 차례를 바꾸지 않는다.

시간/장소 변경은 확인 요청 상태를 표시하고 재확인 기한·미응답 처리 정책을 Gate 4에서 확정한다. 기한 전에 자동 노쇼 처리하지 않는다. 알림 실패 시 운영자는 앱의 미확인 목록과 공식 공지로 확인할 수 있지만 외부 재전달을 정상 성공으로 계산하지 않는다.

## 5. 안전·개인정보·운영 요구

- 신고 진입점: 메시지·공지·그룹 소개·멤버 프로필. 신고는 관련 메시지 ID와 사유를 최소 수집하고 필요한 증거를 제한된 사건 저장소에 보존한다.
- 차단: 해당 상대의 일반 콘텐츠·멘션·개인 프로필 노출·알림·개인 읽음 정보를 상호 제한하는 안을 검증한다. 같은 그룹의 공통 일정·운영 공지는 독립된 공식 객체로 취급한다. 정확한 차단 의미와 예외는 사용자에게 설명하고 Gate 4에서 확정한다.
- 차단이 물리적 만남을 막거나 상대가 이미 본 내용을 회수한다는 약속을 하지 않는다. 위험한 동일 그룹 동석은 신고·운영자 분리·참가 취소/그룹 탈퇴로 처리할 수 있어야 한다.
- 운영자 계정을 차단한 경우에도 공식 일정 상태는 확인 가능해야 한다. 운영자가 일반 대화 권한을 우회해 개인 메시지를 보내지 못하게 한다. DM은 범위에서 제외 제안이다.
- 삭제·강퇴 후 다운받은 파일·스크린샷의 원격 회수는 보장할 수 없다. 서버 제공과 앱 캐시 제한, 알림 프리뷰 최소화의 한계를 고지한다.
- 이미지: MVP 포함 여부 미정. 포함 전 EXIF 제거, 원본 격리, 허용 형식·용량, 악성 파일 검사, 인물 동의·신고, 비공개 접근, 캐시/파생 이미지/백업 삭제까지 정의한다. 공개 버킷과 영구 공유 링크는 금지 제안이다.
- 수집 최소안: 내부 계정 ID, 인증 제공자 식별자, 표시명, 소속·권한, 메시지, 신청·출석. 휴대전화·생년월일·주소록·상시 위치·건강/부상·WOD는 기본 수집하지 않는다. 인증에 이메일이 필요하면 비공개 목적/보관을 별도 정의한다.
- 잠금화면 알림은 메시지 본문·이름·정확한 위치를 숨긴 일반 문구를 기본으로 제안한다. 푸시 토큰은 분석 이벤트나 로그에 기록하지 않는다.
- 18세 이상 검증은 H05 제안일 뿐 확정 연령 정책이 아니다. 미성년자 포함 시 별도 보호·동의·접촉 정책 검토가 선행되어야 한다.
- 그룹 탈퇴 후 메시지/사진 보관, 계정 삭제 시 익명화와 삭제, 신고 증거 보존, 백업 만료 기간은 **열린 결정**이다. 기간 미정 상태로 실제 사용자 데이터를 수집하지 않는다.

운영 계획은 심각한 위해·사칭·괴롭힘·스팸·권리침해·현장 분쟁을 분류하고 안전 담당자, 주말/야간 경로, 목표 응답시간, 제재·이의제기 담당 분리를 정해야 한다. 검토용 산식은 `일일 신고량 × 건당 처리시간 + 긴급사건·이의제기 여유시간`이다. 숫자와 담당자는 미정이며 24시간 대응을 약속하지 않는다. 실제 안전 대응·신고·차단이 없으면 출시 차단이다.

## 6. 인터랙션·접근성 검증 계획

Design Intelligence의 과업·상태 기준만 적용했다. 화면·토큰·컴포넌트·선호 스타일은 만들거나 채택하지 않았다. 사용자 취향은 아직 미확정이며 경쟁 화면을 복제하지 않는다.

| 상태 | 검증할 사용자 경험 |
|---|---|
| 첫 방문/빈 방 | 실제 사람이 시작할 다음 행동과 그룹 목적을 설명; 가짜 활동 없음 |
| 인증 실패/초대 만료 | 입력과 안전한 원래 목적지를 보존; 새 초대 요청 방법과 접근 불가 이유 구분 |
| 긴 대화/긴 이름/큰 글자 | 초점·스크롤 위치 안정, 최신 메시지 이동 선택, 키보드와 스크린리더 전송 가능 |
| 로딩/재접속/오프라인 | 전송 실패를 성공으로 표현하지 않음. 정원은 재연결 후 서버 확인 전 확정 불가 |
| 권한 거부/정지/삭제 | 사라진 메시지와 접근 차단을 구분; 이의제기·안전한 복귀 제공 |
| 알림 소음/권한 거절 | 그룹별 뮤트·알림 기본값 명확. OS 권한 없이도 앱 안에서 확인 가능 |

향후 모바일 실기기·키보드·스크린리더·확대·작은 화면·네트워크 단절에서 핵심 과업을 평가한다. 대비·터치 영역·초점·실시간 읽기 공지·motion 설정은 디자인 단계에서 공식 접근성 기준과 함께 확인한다. 현재 사용성·시각 검증은 **미실행**이다.

## Gate 체계와 현재 판정

| Product Harness 단계 | 저장소 AGENTS.md와의 대응 | 현재 판정 / 이유 | 다음 담당과 통과 증거 |
|---|---|---|---|
| Gate 0 Brief | Intake, Opportunity 진입 | Blocked: 대상·지역·플랫폼·성공/실패 기준 미확정 | 사용자/Product: Q1–Q3와 증거 기반 검증 기준 기록 |
| Gate 1 Discovery | Opportunity | Blocked: 공식 기능 자료만으로 미충족 문제·전환 수요 입증 불가 | Research: 최신 공식/행동 근거, 경쟁·대체재 비교와 반증 |
| Gate 2 Problem | Opportunity→Product | Blocked: 인터뷰·실제 이전/반복 행동 근거 없음 | Research/Product: 반복 JTBD, 실제 비용, 동의한 행동 실험 결과 |
| Gate 3 Business | Product and Business | 선행 조건으로 Blocked / 미평가 | Product/BD: 운영·알림·검수·애셋 비용, 가격/과금 가설, 공급 책임 |
| Gate 4 Solution/UX | Solution | 선행 조건으로 Blocked / 미평가 | Design/Product: 실제 과업·기기·공동성장 프로토타입, 확정 권한/상태 |
| Gate 5 Build Readiness | Solution→Build | 선행 조건으로 Blocked / 미평가 | Architect/QA/Safety: 계약·보안·측정·테스트·복구·운영 승인 |
| Game Concept/Prototype | 추가 확장 Gate | Blocked: 비교 사례/재미·소속감/공정성 시험 없음 | Design/Research/Integrity: 비교 10개 이상 분석, 적정 사용자 시험, 규칙과 조작 반증 |
| 문서 Review L1 | 기계 검증 가능한 문서 변경 | 별도 판정: 링크·상태·diff·기존 린터 검사 | Orchestrator: 실제 검사 결과만 기록 |

문서를 작성했다는 이유로 Product Gate를 Pass 처리하지 않는다. 고객·사용성·Game 시험의 수치 권장은 계획이지 모집/성과가 아니다. 이 작업에서 UI·API·DB·배포·계정 생성·외부 연락·원격 푸시는 하지 않는다.

## 다음 작업의 의존성

아래 역할은 책임 구분이며 실행 중인 하위 에이전트 명단이 아니다. 선행 Gate를 통과하기 전 구현 작업을 시작하지 않는다. `risk`는 미래 실행 시 필요한 검증 수준이며 현재 문서 작성은 L1이다.

각 구현은 writer 1명으로 좁은 흐름을 완성한 뒤 QA/읽기 검토를 받는다. 실패 시 같은 영향 범위만 재작업하고 3회 반복 실패·요구 변경·중대한 불확실성은 원인 Gate로 되돌린다. 이번에는 subagent나 새 작업을 만들지 않았다.

## 운영·공개·복구의 선행조건

신고/긴급 위해/이의제기 담당, 야간·주말 대응, 그룹 공개와 참여자 고지, 메시지·이미지·메타데이터 retention, 집계 k/window/delay, 애셋 귀속·기여 정정, 소유자 이전/해산, 지원 채널·RTO/RPO가 미정이다. 이 항목은 작성자가 문서로 임의 승인하지 않는다.

실제 구현이 허가되더라도 기본 그룹 경계·모더레이션·삭제 계약을 건너뛰고 채팅을 외부에 열지 않는다. 배포는 이번 요청에 없으며 Gate 7과 별도 사용자 권한이 필요하다. 장애·잘못된 공개·보상 조작 때에는 해당 전달/공개/반영을 중단하고 감사·기여 원장을 보존해 복원하는 계획을 먼저 확정한다.

## 이번 문서 변경의 되돌리기

실제 코드·DB 마이그레이션·외부 설정 변화가 없어 운영 rollback은 없다. 새 준비 문서와 기존 index/아키텍처에 추가한 링크만 사용자 검토로 되돌릴 수 있다. 기존 하네스 지침·소스·테스트·의존성·lockfile은 수정하지 않는다. 제품의 구현 rollback 설계와 문서의 되돌리기를 혼동하지 않는다.

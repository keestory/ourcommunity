# 공간과 활기의 레퍼런스 — 대화 원문은 비공개

상태: 조사 결과 전달에 기반한 패턴 제안 / 미승인 미학 · 확인일 2026-10-29

사용자 요구는 비공개 대화의 활발함을 특이한 방식으로 알리는 것이다(E12). 과거 Clubhouse 같은 실제 서비스에서 참고해 달라는 요청(E13)에 따라 아래 공식자료를 검토한 관리 작업의 결과를 받았다. 이 작업에서 직접 서비스를 사용하거나 UI를 캡처·성능/사용성 시험한 것은 아니다. 공식 설명을 제품 효과의 인과 증거로 해석하지 않는다.

관측 주체: 관리 작업의 독립 공식자료 검토. 각 링크의 확인일은 2026-10-29이며 R01의 원문 게시일은 별도 표기했다. 플랫폼 범위는 R01 Clubhouse 앱의 해당 시기 기능, R02 Gather Classic 1.0, R03 Discord 서버 기능, R04 Habitica, R05 Forest이다. 실제 대상 OS 버전·화면 동작·과금 조건 전체는 미확인이다.

출처 수준은 공식 문서 설명(Design Intelligence level 3)에 대한 전달이다. 우리 제품 사용자 시험(level 5)과 운영 효과(level 6)는 없다. 스크린샷·캐릭터·UI·상표·3D 모델은 복제/배포하지 않으며 실제 애셋 제작 시 별도 라이선스를 확인한다. 이 5개 비교는 Game Concept Gate가 요구하는 비교 10개 이상의 완성된 조사와 같지 않다.

## 2. 통합 방향 — 추천 후보, 사용자 확정 아님

**2D 클럽 공간 + 비공개 그룹 채팅 + 일정 + 공동 기념물**을 하나의 후보로 둔다. 기존 앱의 화면 배치를 가져오기보다 아래 세 가지 관계를 검증한다.

1. 문턱: 비회원은 그룹이 무엇을 함께하는지와 공개 동의된 공간만 본다. 채팅·정확한 위치·개인 상태는 보지 못한다.
2. 내부: 가입자는 권한 있는 채팅과 공지·일정을 사용하고, 자기 기여가 어떻게 공동 공간과 연결됐는지 확인한다.
3. 기억: 검증된 공동 활동·도움은 장기 애셋/기념물로 남는다. 최근 분위기와 달리 활동 감소로 사라지지 않는다.

표현 후보는 창문의 따뜻한 불빛, 정원의 움직임, 응원석/작은 축제 분위기 등이다. 특정 예시는 미학의 확정이 아니다. 정확한 사람 수·메시지 수만큼 아바타/창문을 그리지 않는다. 조용한 단계도 불 꺼진 폐허·시든 나무처럼 표현하지 않고, 평온한 장면 등 동등한 완성도의 스타일을 비교한다.

표현의 해석을 확인해야 한다. ‘지금 접속 중’이나 ‘운영자가 바로 답함’으로 오해하면 최근 집계라는 문구와 시각 구분을 수정한다. 소속감과 안심을 목표로 하며 활동 압박·경쟁·가짜 활기를 만들지 않는다.

## 3. 최근 활기와 영구 성장의 분리

| 층 | 원천 | 표시·변화 계약 |
|---|---|---|
| 영구 공동 자산 | 동의/규칙에 따라 검증된 출석·활동·도움·선택적 기록 | 공동 기념물/기억. 최근 대화 감소·휴식으로 몰수/쇠퇴하지 않음. 잘못된 기여/동의 철회는 별도 보정 정책 |
| 최근 활기 | 내용이 아닌 최소 메시지 메타데이터의 보호된 집계 | 넓은 기간의 지연된 coarse 단계. 개인별 접속/정확한 인원/시간/감정 추론 없음. 자산 지급·랭킹과 연결하지 않음 |

대화 내용을 AI로 분석하거나 감정을 추정할 필요가 없다. 메타데이터만으로도 개인을 추정할 수 있으므로 ‘익명이라 안전’이라고 부르지 않는다. 공개 활기 기능은 제품 요구의 한 구현 제안이며 공개 기본값은 꺼짐을 추천한다.

## 4. 집계·공개 계약 초안

- 원천 신호는 일정 기간의 서로 다른 기여자·활동일·고른 참여에 관한 최소 메타데이터다. 개인별 일일 인정량 상한, 시스템/봇/중복/스팸 제외, 연속성 평가를 제안한다. 정확한 가중치·기준은 미정이며 메시지 수를 많이 만들수록 유리한 계산을 피한다.
- 외부에는 승인된 `ActivitySnapshot`의 거친 단계만 제공한다. account/message ID, 본문·인용·감정, 정확한 메시지 시각·온라인 수·개인 활동·날짜별 차트는 제공하지 않는다.
- 최소 **서로 다른 집계 기여자 수** `k_public`, 고정된 넓은 창 `W`, 공개 지연 `D`, 갱신 주기 `R`을 사전에 검증·승인해야 한다. 그룹 명부 인원만 많다고 k를 만족한 것으로 보지 않는다. 값은 아직 제안 전이며 특정 숫자의 안전성을 주장하지 않는다.
- 작은 집단·부족한 기여자·한 사람에게 편중된 활동·삭제 후 기준 미달이면 공개를 억제한다. ‘0명/0건’이나 숨김의 구체 사유를 표시하지 않고 일반적인 비공개 공간으로 보여준다. 공개 차단을 그룹 품질 평가로 표현하지 않는다.
- 고정된 비중첩 구간과 지연·정해진 단계만 제공하는 안을 우선 검토한다. 임의 시작/끝·개인 필터·실시간 재조회·과거 원시 히스토리를 허용하지 않는다. 인접 snapshot 차이·그룹 인원 변화·관측자가 이미 아는 정보와 결합한 추론 공격도 검토한다.
- 운영자의 공개 선택, 모든 멤버의 이해 가능한 고지와 필요한 동의/거부 경로, 신규 가입 안내, 정책 버전을 분리한다. 운영자의 토글 하나가 멤버 프라이버시 동의를 자동 대체하지 않는다. 관할 규칙과 이탈/옵트아웃 처리 확정 전 외부 공개하지 않는다.
- 내부 멤버도 정확한 개인 접속/기여 리더보드를 자동으로 보지 못한다. 운영자는 업무상 필요한 신청·신고 처리만 별도 권한으로 접근한다. 안전 담당자의 사건 데이터와 외부 공개 snapshot은 다른 API/저장·캐시 권한을 갖는다.
- 탈퇴·강퇴·삭제·옵트아웃 시 접근 철회와 데이터 삭제는 승인된 기한대로 처리한다. 공개 기준이 무너지면 즉시 fail-closed로 숨기고 안전한 다음 배치로 재생성한다. 바뀐 정확한 수나 탈퇴자의 기여를 밝히지 않는다. 이미 외부에 저장된 이미지·스크린샷 회수는 보장하지 않는다.
- 내용 비공개와 이용자 친화적 시각화는 보안 보장과 다르다. 작은 그룹의 사실상 신원 추정 위험이 남으면 그 그룹의 공개 활기를 제공하지 않는 것이 유효한 결과다.

## 5. 이해·프라이버시·공정성 시험 계획

같은 합성 데이터를 써서 공간 후보를 비교한다. 활발하지만 한 명만 도배하는 방, 고르게 짧게 대화하는 방, 작은 그룹, 잠시 쉬는 그룹, 사진/이름 공개를 원치 않는 멤버를 포함한다. 외부 관찰자가 개인 존재·특정 날 참여·정확한 수를 추측할 수 있는지와 조용한 공간을 열등하다고 느끼는지 따로 기록한다.

시험 통과 조건의 초안: 참여자가 ‘원문/실시간 사람 수가 아니라 지연된 그룹 분위기’라고 이해하고, 공개/비공개 경계를 예측하며, 휴식에 불이익이 없음을 확인할 수 있어야 한다. 영구 자산과 최근 활기의 차이를 이해해야 한다. 수치 합격선과 실제 대상 표본은 아직 승인되지 않았다.

`AC-G03/G05/G06`, `QA-29–34`와 연결한다. 현재 이 시험·렌더링·AI 분석·집계 구현은 **실행하지 않았다**. 채택한 디자인/패턴은 아직 없고 모든 공간 방향은 `candidate`다.
